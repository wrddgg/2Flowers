# 图片视觉语义抽取方案

## 1. 目标

把当前基于 `content_id / group_id / image_url` 的规则映射，升级为真正基于图片内容的语义抽取，支持：

- 自动判断 `scene / flower / life`
- 自动提取 `emotion_tags / scene_tags / visual_tags / color_palette`
- 对花束图补充 `main_flowers / package_style / fit_for`
- 为后续参考检索、生成、情绪承接提供更稳定的输入

## 2. 建议方案

采用“两阶段抽取”：

1. 视觉基础抽取
   - 输入：原图或裁剪框区域
   - 输出：颜色、主体类型、构图、是否有人物、是否是花束、是否是空间场景

2. 语义标签归一化
   - 输入：视觉基础结果 + 用户语音文本
   - 输出：项目内统一标签体系
   - 例如把“蓝白、安静、窗边下雨、适合送朋友”归一到现有 JSON 标签字段

## 3. 模型分层

### 3.1 轻量视觉层

适合先落地，优先保证可用：

- `CLIP / SigLIP`：做图文相似度匹配
- `GroundingDINO` 或同类检测模型：识别花、人、桌面、窗、海边等主体
- 简单颜色聚类：提取主色板

这一层解决：

- 这更像 `scene`、`flower` 还是 `life`
- 图里是不是花束
- 图里更偏窗边雨景、海边、餐桌、房间等哪一类

### 3.2 多模态语义层

用多模态大模型做高阶解释：

- 识别情绪：克制、治愈、纪念感、祝贺感、轻家居感
- 识别关系语境：生日朋友、感谢领导、妈妈节日
- 识别花艺风格：冷感蓝白、奶油白、香槟祝贺、野生自然感

建议输出不要直接放任意自然语言，而是约束成固定字段：

```json
{
  "mode": "scene",
  "emotion_tags": ["轻治愈", "安静"],
  "scene_tags": ["窗边", "雨天"],
  "visual_tags": ["冷色", "留白", "柔光"],
  "color_palette": ["blue", "gray", "white"],
  "confidence": 0.86
}
```

## 4. 工程实现路径

### 阶段 A：素材库检索式抽取

先不直接“理解一切图片”，而是把输入图和现有素材库做相似度匹配。

流程：

1. 为 `annotated_asset_library.json` 每张图片预计算 embedding
2. 用户上传图片后抽 embedding
3. 检索最相近的 `top_k` 素材图
4. 聚合这些素材图所属分组的标签
5. 输出统一语义结果

优点：

- 和你现在已有的素材库天然兼容
- 不需要一开始就训练模型
- 非常适合 Hackathon 到 MVP 这段阶段

### 阶段 B：检测 + 标签融合

在相似度检索之外加入检测结果：

- 花束检测
- 人物/手持检测
- 桌面/窗边/海边/室内场景检测
- 颜色聚类

然后把这些信号和相似素材库结果一起融合打分。

### 阶段 C：多模态 LLM 解释层

在得到候选标签后，再让多模态模型做：

- 歧义消解
- 情绪解释
- 输出自然语言总结

这一层负责提升“像产品”的感觉，但不应成为唯一结构化来源。

## 5. 与当前后端的对接方式

建议新增一个服务，例如：

- `app/services/vision_semantic_extractor.py`

接口输入：

- `image_url`
- `selection_box`
- `voice_text`

接口输出：

- `mode`
- `subject_tags`
- `scene_tags`
- `emotion_tags`
- `visual_tags`
- `color_palette`
- `fit_for`
- `confidence`
- `matched_asset_groups`

然后在 `routes_input.py` 中接入：

1. 先尝试通过 `content_id / image_url` 命中已有素材
2. 如果未命中，则调用 `vision_semantic_extractor`
3. 把结果合并进当前 `semantic_parser`

## 6. 数据准备要求

为了让视觉抽取更稳定，建议继续补这几类标注：

- 每张图保留所属 `group_id`
- 每张图保留一级模式：`scene / flower / life`
- 每组图保留统一标签，不同图片可补充个体差异标签
- 花束图尽量补：
  - 主花
  - 辅助花
  - 包装风格
  - 手持 / 桌摆 / 成品图

## 7. 推荐落地顺序

1. 先做 embedding 检索版
2. 再加颜色和目标检测
3. 最后接多模态模型做解释增强

## 8. 当前最合适的技术路线

如果目标是近期可交付，我建议：

1. 用现有标注图片做 embedding 索引
2. 新增 `vision_semantic_extractor.py`
3. 先返回结构化标签，不急着做自由描述
4. 等接口稳定后，再接多模态模型补解释文案

这样改造成本最低，也最贴合你当前这套真实素材资产。
