# 素材收集与标注注意事项

## 1. 目标

这份文档用于约束 `万物生花` 项目的素材收集、图片命名和标注格式，确保后续可以稳定导入后端知识库，而不是停留在“看得懂但程序不好读”的状态。

## 2. 收集原则

### 2.1 先够用，再扩量

- 当前阶段优先收集“能支撑 Demo 的代表性图片”
- 不强制要求完整短视频
- 不强制要求同一条视频补多帧
- 一组素材中，优先保留最有代表性的 `1-4` 张

### 2.2 三类素材要分开

所有素材都必须先归入以下三类之一：

- `scene`：场景生花
- `flower`：花再生
- `life`：人生生花

如果一张图同时像多个类别，以“后续要支撑的交互”为准：

- 画面意境优先，归 `scene`
- 现成花束优先，归 `flower`
- 关系表达优先，归 `life`

### 2.3 不要只存图片，不存上下文

至少保留下面任一类上下文：

- 原始标题
- 素材来源
- 人工归纳后的主题名

如果完全没有上下文，后续再做批量结构化会很费时间。

## 3. 图片命名规范

### 3.1 统一命名格式

图片文件名统一使用：

```text
{group_id}_{序号}.png
```

示例：

- `scene_sunset_01.png`
- `flower_blue_white_02.png`
- `life_promotion_friend_03.png`

### 3.2 group_id 规范

- 场景组：`scene_xxx`
- 花束组：`flower_xxx`
- 人生组：`life_xxx`

建议只使用：

- 小写英文
- 下划线
- 不使用空格
- 不使用中文

### 3.3 命名时避免的问题

不要使用以下形式作为长期命名：

- `图片1.png`
- `最终版.png`
- `抖音截图(2).png`
- 带空格或括号的临时命名

这些命名对人工可读，但对程序批处理很不友好。

## 4. 标注原则

### 4.1 每组素材优先按“标题组”标，不逐张重复写

推荐按一个主题写一组，而不是每张图写一条。这样更适合当前 Demo 阶段。

### 4.2 标签写短词，不写散文

推荐：

- `冷色`
- `留白`
- `治愈`
- `克制`
- `升职`
- `朋友`

不推荐：

- `这个画面给人一种微妙而朦胧的安静感`

长句请放在 `summary`，不要塞进 tags。

### 4.3 标注时区分三类标签

- `visual_tags`：画面长什么样
- `emotion_tags`：情绪是什么
- `scene_tags`：使用场景是什么

示例：

- `visual_tags`: `蓝白`、`留白`、`清透`
- `emotion_tags`: `克制`、`治愈`
- `scene_tags`: `探望`、`送礼`、`同事`

## 5. 不同类型素材的额外要求

### 5.1 scene

至少补：

- `group_id`
- `title`
- `summary`
- `visual_tags`
- `emotion_tags`
- `scene_tags`
- `recommended_bouquet_id`

### 5.2 flower

除了通用字段，还应尽量补：

- `main_flowers`
- `secondary_flowers`
- `package_style`
- `fit_for`
- `avoid_for`

如果花材识别不全，最低要求是：

- 至少 1 个主花
- 至少 1-2 个辅助花或叶材

### 5.3 life

除了通用字段，还应尽量补：

- `target_relation`
- `expression_tone`
- `recommended_bouquet_id`
- `alternate_bouquet_id`
- `avoid_direction`

## 6. 推荐花束引用规范

引用花束时优先写统一 id，不要只写中文名。

推荐写法：

- `recommended_bouquet_id: flower_champagne_congrats`
- `recommended_bouquet_title: 香槟祝贺花束`

这样既方便程序处理，也保留人工可读性。

## 7. 文档格式建议

推荐在 Markdown 文档里按以下结构写：

```text
- group_id：life_promotion_friend
- mode：life
- title：升职朋友
- images：life_promotion_friend_01.png、life_promotion_friend_02.png
- summary：朋友进入新阶段，适合明亮、体面、不过甜的祝贺表达。
- visual_tags：明亮、利落、体面
- emotion_tags：祝贺、积极、克制
- scene_tags：升职、朋友、送礼
- target_relation：朋友
- expression_tone：别太甜，偏祝贺
- recommended_bouquet_id：flower_champagne_congrats
```

## 8. 最低可交付标准

如果时间紧，至少满足下面这版：

- 每组有 `group_id`
- 每组有 `mode`
- 每组有 `title`
- 每组有 `images`
- 每组有 `summary`
- 每组有 3 个以上标签
- `flower` 组至少有主花
- `life` 组至少能映射到一组花束

达到这一步，就已经足够接入 Demo 后端。

## 9. 常见问题

### 9.1 如果图片很多，但标注时间不够怎么办

先做“组级标注”，不要追求逐张精标。

### 9.2 如果花材不确定怎么办

可以先标“按画面判断”，后续再二次校正。

### 9.3 如果一张图既像场景又像人生怎么办

按它后续最主要服务的功能归类，不要一图多类重复入库。
