# Prompt 审查报告

## 1. 本轮目标

本轮不是单纯润色文案，而是按完整业务流程重新审视 prompt：

1. 输入图先被多模态模型识别成结构化语义
2. 结构化语义进入参考检索
3. 检索结果和语义再进入远端生图模型
4. 最终输出的是“可展示、可售卖、可解释”的花束结果

因此 prompt 的职责必须围绕两个第一性原理：

- **识别 prompt** 要服务于“匹配”，而不是服务于泛图像描述
- **生图 prompt** 要服务于“转译”，而不是把输入场景或参考花束直接复刻出来

## 2. 旧版本的主要问题

### 语义识别 prompt

旧版本更像是字段抽取说明，问题在于：

- 只强调了输出 JSON，没有强调“什么语义才值得提取”
- 没有明确图片区别 `scene / flower / life` 的判定边界
- 没有明确“图片事实优先，文本只做补充”
- 没有强调 taxonomy 是候选，不是强制照抄

### 生图 prompt

旧版本更像信息拼接，问题更明显：

- `style_prompt` 和 `negative_prompt` 建好了，但实际最终 prompt 没有充分利用
- 没有明确 `scene` 输入应被“翻译成花束”，容易被模型直译成窗边、雨夜等背景
- 对参考图的约束不够精确，容易变成“像参考图本身”
- 缺少明确的商品图要求和负向约束

## 3. 本轮优化原则

### 语义识别侧

- 抽取后续花艺匹配真正需要的语义
- 优先抓氛围、色调、质感、关系、用途
- 明确 mode 定义边界
- 明确图片事实优先、文本补充 use_intent
- 输出控制在简洁标签与一句摘要内

### 生图侧

- 明确最终产物必须是单束鲜花商品图
- 明确 `scene` 是转译，不是复现空间
- 明确参考图只能借鉴，不可照搬
- 明确画面约束与商品约束
- 明确负向约束，减少脏背景、人物、花瓶、插画感

## 5. 当前采用的语义识别 Prompt

以下为当前代码按“窗边雨夜 -> 送朋友”样例生成出的实际 prompt：

```text
你是“万物生花”的多模态语义识别器，目标不是写一段泛化图像描述，而是提取后续花艺匹配真正需要的语义。
请结合图片、selection_box 焦点区域和用户补充文本，输出一个严格 JSON 对象。

判断优先级：
1. 先判断输入属于哪一类：scene 表示氛围/空间/景别，flower 表示花束或花艺成品本身，life 表示带有人际关系、送礼对象或人生事件的现实场景。
2. 先尊重图片里真实可见的信息，再用用户文本补充 use_intent、关系对象和用途，不要让文本覆盖明显的视觉事实。
3. 只提取能转译为花艺方案的语义，例如氛围、色调、质感、关系、场景和用途；不要沉迷于无关细节、品牌、文字或复杂背景。
4. taxonomy 和 candidate_tags 只是候选约束，不是必须照抄；只在确实匹配图片或文本时选择。

输出规则：
1. mode 只能是 scene / flower / life。
2. confidence 返回 0 到 1 的小数。
3. evidence 提供 2 到 4 个短语，说明你为什么这样判断。
4. subject_tags、scene_tags、emotion_tags、visual_tags、relation_tags、color_palette 都尽量短，单项最多 4 个。
5. scene_tags、emotion_tags、visual_tags、relation_tags 尽量优先从 taxonomy 中选；没有合适项时再给自然但简洁的中文标签。
6. use_intent 只能是 表达氛围 / gift / self / decorate / celebrate。如果缺乏明确送礼或装饰意图，scene 默认优先考虑“表达氛围”。
7. semantic_summary 用 1 句话概括这张图最终想传达并适合被转成花束的感觉。
8. raw_caption 用 1 句话忠实描述可见内容。
9. 只返回 JSON 对象，不要 Markdown，不要解释，不要额外字段。

selection_box={"x": 12, "y": 16, "width": 180, "height": 140}
voice_text=想把这个画面的安静和轻治愈感，变成一束可以送朋友的花。
taxonomy={"allowed_modes": ["scene", "flower", "life"], "scene_tags": ["窗边", "雨天", "室内"], "emotion_tags": ["安抚", "内向", "轻治愈"], "visual_tags": ["玻璃雨滴", "模糊背景", "暖灯", "近景质感"], "relation_tags": [], "use_intents": ["表达氛围", "gift", "self", "decorate", "celebrate"], "candidate_tags": ["窗边雨幕", "蓝白克制花束", "窗边", "雨天", "室内", "安抚", "内向", "轻治愈", "玻璃雨滴", "模糊背景", "暖灯", "近景质感"]}

输出 JSON 结构：{"mode":"scene","confidence":0.85,"evidence":["..."],"subject_tags":["..."],"scene_tags":["..."],"emotion_tags":["..."],"visual_tags":["..."],"color_palette":["..."],"relation_tags":["..."],"use_intent":"表达氛围","semantic_summary":"...","raw_caption":"..."}
```

## 6. 当前采用的生图 Prompt

以下为当前代码按“scene + 蓝白参考花束”样例生成出的实际 prompt：

```text
你要为“万物生花”生成一张可直接用于前端展示的花束商品图。
最终结果必须是一束完整、真实、可售卖的鲜花花束成品，而不是场景照、概念海报或插画。
产品模式：scene
创作任务：先理解输入语义，再把它翻译成花束的配色、花材气质、层次结构、包装方式和整体留白。
风格设定：
把输入语义翻译成一束可售卖、可展示、可落地的真实花束成品图。
请把场景氛围转译成花束，不要把原始空间直接画出来；重点体现色调、情绪、留白和气质。
核心氛围：把雨夜窗边的安静、克制和轻柔治愈感转成一束适合送朋友的花。
场景线索：窗边、雨天、室内
情绪目标：安抚、内向、轻治愈
视觉倾向：蓝白、留白、朦胧光点
建议配色：蓝灰、白色
关系对象：朋友
参考强度：light
场景标签：窗边、雨天、室内
情绪标签：安抚、内向、轻治愈
视觉标签：蓝白、留白、朦胧光点
关系标签：朋友
用途意图：gift
参考花束：蓝白克制花束。请借鉴这些参考的颜色方向、结构层次、包装气质和花材倾向，但不要复刻同一束花，不要照抄构图，也不要让结果看起来像参考图的直接翻版。
画面要求：单束花束，主体完整，花头和包装清晰，构图稳定，背景干净，光线自然柔和，真实摄影质感。
商品要求：鲜花新鲜、有层次、有手工包扎感，适合花店商品卡、详情页或结果页展示。
明确避免：不要文字、logo、水印、价签；不要人物、手部、花瓶、桌面陈列；不要多束花同时出现；不要插画感、CG 感、塑料假花感；不要畸形花头、重复花材、背景杂乱、主体被裁切、过曝或低清晰度。
```

## 7. 本轮优化后的直接收益

### 对语义识别

- 更容易把模型注意力集中到“可转译语义”
- 更容易减少无关细节和过度叙述
- 更容易稳定 `scene / flower / life` 的边界

### 对生图

- 更明确地区分“借鉴参考”和“复制参考”
- 更明确地区分“场景氛围转花束”和“把场景画进图里”
- 更明确地面向商品展示结果，而不是艺术化概念图

## 8. 仍需继续观察的点

1. 目前生成结果仍可能残留一定“场景直译”倾向。  
   这次反向语义复核里，生成图仍带有 `窗边 / 雨天 / 室内` 标签，说明还要继续观察远端模型是否把 prompt 理解得过于字面。

2. 三张结果的差异性偏弱。  
   当前 prompt 更偏保守稳态，后续如果你们想强化展示效果，可以增加“同主题下的三个不同包装/层次方案”的明确约束。

3. taxonomy 仍然是双刃剑。  
   它能提升稳定性，但也可能让模型过度贴近素材库已有标签。后续如果素材库扩大，需要控制 taxonomy 粒度。

## 9. 下一步建议

- 给 `scene`、`flower`、`life` 各挑 1 个正式样例，固化成 prompt 回归样本
- 在生图后做一次自动反向识别，检查是否出现“把原始场景直接画进商品图”的偏差
- 若要提升多样性，可在 prompt 中显式要求 3 张分别偏：
  - 更轻包装
  - 更空气感
  - 更结构层次
