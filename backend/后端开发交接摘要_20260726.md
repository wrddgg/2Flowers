# 万物生花后端开发交接摘要

## 1. 项目目标

“万物生花”后端的目标，是把用户输入的场景、人像、花束或现实情境，转成可展示、可编辑、可情绪承接的花艺结果。

当前主链路为：

`输入分析 -> 参考检索 -> 花束生成 -> 花材详情 -> 花束编辑 -> 情绪承接`

技术栈：

- Python 3.10+
- FastAPI
- Pydantic v2
- httpx
- 本地 JSON 素材库 / 知识库

## 8. 当前用户最在意的问题

接手后务必优先理解这几点：

1. 用户不希望“参考图 = 直接复刻”
2. 用户不希望为了体现参考，把所有颜色和花材硬塞在一起
3. 用户认同“克制、重复、统一色块、少量花材”更接近好花束审美
4. 用户希望过程报告默认带：
   - 每个阶段的 prompt
   - 输入图
   - 参考图
   - 结果图
5. 用户接受这一阶段先停在“有明显改进，但仍可继续优化”的状态

---

## 9. 目前已验证有效的方向

- 引入独立规划模型，而不是让识图模型兼做审美规划
- 用多专家角色 prompt 替代“一个模型包办一切”
- 在 prompt 中明确：
  - 参考是灵感，不是元素清单
  - 可以主动舍弃不匹配颜色和元素
  - 花材必须真实存在
- 通过正式流程报告不断对照图像结果，而不是只看 JSON 输出

---

## 10. 下一阶段最值得做的事

如果后续有其他模型继续接手，最建议的优先顺序是：

1. **把参考素材补充“形式美学字段”**
   - 如：铺陈型 / 留白型 / 单花材主导 / 色块型 / 层次型

2. **把识图色板与生花色板真正解耦**
   - 识图可以保留丰富信息
   - 规划阶段再决定每个方案真正采用哪些颜色

3. **继续优化规划模型输出**
   - 重点看它是否真的会“主动舍弃”
   - 而不是只会生成看起来不同的文案

4. **为正式 API 流程固化更多样例报告**
   - `scene`
   - `flower`
   - `life / portrait`
